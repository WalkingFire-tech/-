# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in Alliance Pioneer, please report it responsibly:

- **Email**: kun_phone@139.com
- **Do not** open a public GitHub issue for security vulnerabilities

We will acknowledge your report within 48 hours and provide a detailed response within 7 days.

## Security Architecture

Alliance Pioneer implements a 4-layer defense system:

| Layer | Function |
|-------|----------|
| L1 Prevention | Input validation, injection detection |
| L2 Monitoring | Anomaly detection, circuit breaker protection |
| L3 Handling | Fault isolation, resource reallocation |
| L4 Repair | Auto-restart, state recovery |

### Sandboxed Code Execution

- Tool code generated by the system runs in a sandboxed environment
- Dangerous modules (`os`, `sys`, `subprocess`) are blocked by default
- Hardware access (serial port, system commands) requires explicit capability creation loop activation
- All shell commands pass through a dangerous command filter

### Data Safety

- No credentials or API keys are stored in the repository
- `.env` files are excluded from version control via `.gitignore`
- Database files contain only local runtime data and are not committed

## Meta-Constitution

The system operates under three inviolable rules:

1. **R1**: Unverified truths are treated as poison
2. **R2**: Ungraduated restructuring is treated as suicide
3. **R3**: Unapproved evolution is treated as betrayal

These rules ensure the system cannot self-modify in dangerous ways without human oversight.
