# 启动脚本修复报告

## 问题描述

用户反馈：需要两次启动才能打开前端界面。

### 错误信息

```
'5]' is not recognized as an internal or external command,
operable program or batch file.
[警告] 后端可能未完全启动，请稍后手动访问 http://localhost:8000
```

## 问题原因

### 1. 括号解析错误

**问题代码**：
```batch
echo 等待后端启动（5秒）...
```

**原因**：批处理将 `（5秒）` 中的中文括号误解析为命令，导致 `'5]'` 错误。

**修复**：
```batch
echo 等待后端启动...
```

### 2. 健康检查路径错误

**问题代码**：
```batch
curl -s http://localhost:8000/health >nul 2>&1
```

**原因**：健康检查端点应为 `/api/health`，而非 `/health`。

**修复**：
```batch
curl -s http://localhost:8000/api/health >nul 2>&1
```

### 3. 启动等待时间不足

**问题**：固定等待5秒，但后端初始化可能需要更长时间（加载模型、组件等）。

**修复**：使用循环检测，最多等待30秒。

## 修复方案

### 已修复的文件

1. **`start.bat`** - 主启动脚本
   - 移除中文括号
   - 修正健康检查路径

2. **`scripts/start_all.bat`** - 完整启动脚本

### 核心改进

1. **智能等待**：循环检测健康端点，最多等待30秒
2. **实时反馈**：显示等待进度和耗时
3. **正确路径**：使用 `/api/health` 端点
4. **环境变量**：自动设置 HuggingFace 镜像等
5. **错误处理**：超时后仍尝试打开浏览器

### 核心代码

```batch
REM 等待后端启动（最多30秒）
set /a count=0
:wait_loop
set /a count+=1
if %count% gtr 30 (
    echo [警告] 后端启动超时，但服务可能仍在初始化中
    goto open_browser
)

REM 检查健康端点
curl -s http://localhost:8000/api/health >nul 2>&1
if errorlevel 1 (
    ping 127.0.0.1 -n 2 >nul
    goto wait_loop
)

echo  ✓ 后端已就绪 (耗时: %count%秒)
```
