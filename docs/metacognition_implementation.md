# 元认知循环实现报告

## 核心理念

> **不是让系统被动地学习知识，而是让它主动地提升自己的思维框架和能力边界。**

这是自我进化系统的真正核心——**元认知循环**。

---

## 实现的完整循环

```
用户对话 → 系统作答 → 自我复盘 → 老师评估 → 提炼方法论 → 内化为能力 → 下次更好
```

---

## 已实现的模块

### 1. 系统自我复盘 ✅

**文件**: `core/self_reflection.py`

**功能**: 让系统主动审视自己的思考过程

**输出**:
```python
{
    'what_i_did_well': ['回答质量较高', '运用了知识'],
    'what_i_could_improve': ['可能遗漏关键点'],
    'alternative_approaches': ['可以从多角度解释'],
    'uncertainties': [],
    'next_time_strategy': '重点改进: ...',
    'confidence_level': 0.84,
    'reflection_depth': 'medium'
}
```

**分析维度**:
- 优势分析（做得好的地方）
- 劣势分析（可改进的地方）
- 替代方案思考
- 不确定性识别
- 下次策略制定

---

### 2. DeepSeek老师接口 ✅

**文件**: `core/teacher_interface.py`

**角色**: 思维教练（不是裁判）

**评估维度**:
1. **问题拆解能力**（1-10分）：是否准确识别问题核心？
2. **分析框架**（1-10分）：思考结构是否清晰？
3. **假设检验**（1-10分）：是否识别并检验关键假设？
4. **知识运用**（1-10分）：是否正确运用已有知识？
5. **改进建议**：具体、可操作的建议
6. **学习方向**：建议补充哪些知识或能力
7. **方法论提炼**：可复用的思维方法

**特性**:
- API调用失败时自动降级为本地评估
- 速率限制保护
- 调用历史记录

---

### 3. 方法论提取器 ✅

**文件**: `core/methodology_extractor.py`

**功能**: 从老师反馈中提炼可复用的思维方法

**提取的方法论类型**:

| 方法论 | 描述 | 触发条件 |
|--------|------|----------|
| **分层拆解法** | 将复杂问题分解为多个子问题 | 问题包含多个要素 |
| **结构化分析法** | 建立清晰的思考框架 | 需要系统性思考 |
| **假设验证法** | 识别并验证关键假设 | 涉及因果关系推断 |

**应用步骤示例**（分层拆解法）:
1. 识别问题的核心要素
2. 将问题拆分为3-5个子问题
3. 分别处理每个子问题
4. 整合结果形成完整答案

## 完整流程示例

### 场景：低质量回答

**问题**: "为什么会有冰雹?"

**回答**: "冰雹是一种天气现象。"

**步骤1: 自我复盘**
```
做得好的地方: ['完成了基本的问答任务']
可改进的地方: [
    '回答质量偏低，需要提升',
    '未运用已有知识',
    '回答过于简短',
    '思考过程不够深入'
]
置信度: 0.54
反思深度: deep
```

**步骤2: 老师评估**
```
问题拆解能力: 5/10
分析框架: 5/10
假设检验: 6/10
知识运用: 7/10
改进建议: ['回答质量偏低，需要提升', '未运用已有知识']
学习方向: ['加强知识储备', '提升思考深度']
```

**步骤3: 提炼方法论**
```
方法论1: 分层拆解法
  - 描述: 将复杂问题分解为多个独立子问题
  - 触发条件: 问题包含多个要素
  - 应用步骤: 识别核心要素→拆分子问题→分别处理→整合结果

方法论2: 结构化分析法
  - 描述: 建立清晰的思考框架
  - 触发条件: 需要系统性思考
```

**步骤4: 下次策略**
```
重点改进: 未运用已有知识
尝试方法: 可以从定义、特征、例子多角度解释
继续保持: 完成了基本的问答任务
```

## 长期演化路径

### 第一阶段：依赖老师（当前）
- 每次重要对话后调用老师评估
- 提炼方法论并存储
- 积累案例库

### 第二阶段：部分自训练（3-6个月后）
- 建立案例库
- 新问题先检索相似案例
- 复用成功经验
- 老师调用频率下降

### 第三阶段：自我教练（长期）
- 用内化的方法论评估自己
- 外部依赖大幅降低
- 能力持续提升

## 触发条件配置

```yaml
teacher:
  enabled: true
  triggers:
    negative_feedback: true      # 用户给负面反馈
    low_objective_score: 30.0    # 客观分低于30
    novel_question: true         # 从未见过的问题类型
    random_sampling: 0.1         # 10%随机抽样学习
  
  rate_limit:
    max_calls_per_day: 50
    min_interval_seconds: 300    # 至少间隔5分钟
```

---

## 成本控制

- **速率限制**: 最少间隔5分钟
- **触发条件**: 仅在必要时调用
- **本地降级**: API失败时使用本地评估
- **随机抽样**: 10%的普通对话也学习
