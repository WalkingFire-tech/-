## 🔄 版本命名规范

### 版本号规则

- **主版本号**: 重大架构变更 (v1.0 → v2.0)
- **次版本号**: 功能模块新增 (v2.0 → v2.1)
- **修订号**: Bug修复优化 (v2.0.0 → v2.0.1)

### 归档命名

```
archives/v{版本号}/
├── ARCHITECTURE.md       # 架构文档
├── IMPLEMENTATION.md     # 实施报告
```

## 📝 归档更新流程

1. **版本发布前**:
   ```bash
   # 创建归档目录
   mkdir -p archives/v{新版本号}
   
   # 复制关键文档
   cp *.md archives/v{新版本号}/
   ```

2. **更新归档文档**:
   - 更新 `docs/ARCHIVE_v{版本号}.md`
   - 更新文件清单和实现度
   - 记录核心改进

3. **更新进度文件**:
   - 更新 `docs/PROGRESS.md`
   - 标注当前版本
   - 记录下一步计划

4. **清理主目录**:
   - 移除旧版本文档
   - 保留最新版本
