**目标**: 让系统朝着合理方向完善

---

## 🎯 问题分析

### 原始问题

从用户日志发现的关键问题:

1. **多行输入被拆分** - CLI按行读取,每行独立处理
2. **意图识别不准** - 技术文档被误识别为code意图
3. **模型不匹配** - mindchat(心理模型)不适合技术内容
4. **质量评分低** - 40-60分,效果不佳

---

## ✅ 实施的改进

### 1. 增强CLI - 支持多行输入

**文件**: `adapters/ui/cli_ui.py`

**新增功能**:
- ✅ 多行输入模式 (`:ml` 或 `:multiline` 命令)
- ✅ 文件输入命令 (`:file <路径>`)
- ✅ 文件夹输入命令 (`:folder <路径>`)
- ✅ 帮助命令 (`:help`)
- ✅ Ctrl+C取消多行输入

**使用示例**:
```
你: :ml
多行输入模式 (输入 :end 结束, Ctrl+C 取消)
  1| ## 项目状态
  2| - 核心框架：六边形架构
  3| - 已实现能力：
  4|   - 意图识别
  5| :end
✓ 已输入 4 行,共 150 字符
```

---

### 2. 增强意图识别 - 新增document类型

**文件**: `core/services/intent_parser.py`

**新增意图类型**:
- ✅ `document` - 识别技术文档、项目状态等

**识别规则**:
```python
"document": re.compile(
    r"^##|^\*|^- |项目状态|已实现|核心框架|^\d+\.|能力|功能|特性",
    re.IGNORECASE
)
```

**优先级调整**:
```python
priority = {
    "feedback": 10,
    "calculation": 9,
    "document": 8,  # 新增
    "code": 7,
    "memory": 6,
    "question": 5,
    "chat": 1
}
```

---

### 3. 智能模型路由 - 文档使用代码模型

**文件**: `core/services/planner.py`

**新增路由逻辑**:
```python
# 文档类任务使用代码模型
if task_type == "document":
    return self.adapters["code_light"]

# 长文本(>500字符)使用代码模型
if len(intent.raw_text) > 500:
    return self.adapters["code_light"]
```

**原因**: qwen2.5-coder等代码模型更适合处理技术文档
