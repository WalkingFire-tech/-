## 一、核心愿景

**从"替系统修工具"到"让系统学会造工具"** — 系统不应该按照既定的东西去执行，而是学会掌握解决问题的方法，然后不断优化这种解决问题方法的能力。工具应该是系统临时造的，而不是开发者修改的。

> "孩子终归要自力更生的，要让其具备真正的这种能力，才可以适应，才可以后面真正学会去尝试，学习，进步，拓展自己的能力。否则永远是在大树下长不大的幼苗。"

## 二、核心原则（不可违背）

1. **永不放弃** — 问题没有解决不了的，只有想不想得到方法
2. **追求本质** — 从第一性原理出发
3. **先规划，再更新行动指南，然后按步骤执行**
4. **代码验证靠运行而非推理**
5. **三思后行** — 先理解全景再审视局部，先搜索既有讨论再行动，先根因思考再修复
6. **不再替系统做决定，而是让系统自己做决定** — 不替系统修工具，让系统自己修；不替系统加约束，让系统自己学

## 三、元宪法铁律

- R1: 未经沙盒验证的真谛，视同毒药
- R2: 未经渐进注入的重组，视同自杀
- R3: 未经人类允许的进化，视同背叛
- R4: **七维自检** — 行动前必须通过：①方向一致 ②看板衔接 ③最小侵入 ④无过度设计 ⑤治标+治本 ⑥可验证 ⑦精神内核对齐

## 四、行动前自检流程（R4强制）

每次修改代码或提出方案前，必须完成：

1. **理解全景** — 架构、哲学、看板历史、路线图阶段，不盯着局部
2. **搜索既有讨论** — 看板/路线图/架构分析，不重新发明轮子
3. **根因思考** — 问题是孤立故障还是未落地的架构原则？
4. **标本兼治** — 热修复(P0)与架构方案分离
5. **七维自检** — 全部通过才行动
6. **最优判断** — 依赖链排序，不做的事也明确列出

## 五、用户关键指令

- **start.bat必须是最终启动方式** — 每次修改完毕后确保start.bat可用
- **不要杀进程重启服务** — Windows上`--reload`不可用，需手动重启
- **文档只是一个建议** — 可以自由行动，按最稳妥最优的方式执行
- **任何人改 chat_stream.py 时，在 commit message 末尾加 [chat_stream] 标记**
- **文档是实时更新的** — 每次执行前必须重新读取PHASE2_ARCHITECTURE.md和留言板
- **API是手段不是目的** — 系统先用自己的能力解决问题，API只是补充
- **不达目的不罢休** — 在未达到用户真正目的之前，不接受半成品输出
- **知识库不能忘** — 有用的东西必须写入knowledge_base
- **行动指南必须更新** — 每次总结后更新行动指南到docs/sessions/
- **不照搬外部代码** — 按七维自检提取真正新价值，避免与已有实现重复
- **不要新建模块，用现有模块增强** — 新概念应融入现有模块，而非创建新目录
- **服务器需要重启才能使修改生效**

#### 7.6.1 CMD窗口弹出修复（P0）

**问题**：隔一段时间CMD窗口自动跳出然后关闭。

**根因**：
1. `start.bat` 第73行 `start "" cmd /c "timeout /t 20..."` 弹出CMD窗口等20秒后打开浏览器
2. 10个运行时文件的 `subprocess.run()` 缺少 `creationflags=subprocess.CREATE_NO_WINDOW`
3. `start_smart.py` 的 `subprocess.Popen` 缺少 `CREATE_NO_WINDOW`

**修复**：
- `start.bat`: 浏览器延迟启动改为 `powershell -WindowStyle Hidden` 完全隐藏
- 12个运行时文件: 所有 `subprocess.run/Popen` 添加 `creationflags=subprocess.CREATE_NO_WINDOW`

#### 7.6.2 异常透明度整治（P1 — 留言板"断裂三：异常信号断裂"根除）

**问题**：全项目运行时代码中约390处 `logger.debug` 在 `except Exception` 后面，生产环境默认不输出，异常完全不可见。另有302处 `except Exception: pass` 静默吞掉异常。

**修复**：
- `logger.debug` → `logger.warning`（"跳过"类降级操作）或 `logger.error`（"异常/失败"类关键路径）
- `except Exception: pass` → `except Exception as e: logger.warning(f"操作降级跳过: {e}")`
- 全项目运行时代码 `DEBUG_ON_EXCEPTION` 从 ~390 → **0**
- 全项目 `except Exception: pass` 从 302 → **0**
- 全项目裸 `except:` 保持 **0**
