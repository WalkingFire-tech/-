## 一、核心愿景

**从"替系统修工具"到"让系统学会造工具"** — 系统不应该按照既定的东西去执行，而是学会掌握解决问题的方法，然后不断优化这种解决问题方法的能力。工具应该是系统临时造的，而不是开发者修改的。

> "孩子终归要自力更生的，要让其具备真正的这种能力，才可以适应，才可以后面真正学会去尝试，学习，进步，拓展自己的能力。否则永远是在大树下长不大的幼苗。"

### 当前真实位置

项目已从"功能集合"走到"认知架构闭环"，7步闭环（感知→分解→执行→自察→抽象→沉淀→进化）全部有实现。M2场域层已贯通感知端+消费端。**现在需要的是让闭环真正自驱运转**——不是每次由开发者接线，而是系统自己发现断裂、自己修复。

### 宏大方案vs现有架构对比结论

**宏大方案提出的80%能力已存在于代码中**。差距不在"缺失模块"，而在"断开的管线"。宏大方案的真正价值是提供了**统一概念框架**——告诉开发者现有模块应该被如何看待、如何连接、如何进化：

| 宏大方案概念 | 现有模块 | 概念升维 |
|-------------|---------|---------|
| 信息素场 | CBNR L3 认知残差 | "残差计算器"→"场域感知引擎" |
| 场域稳定性 | `_perceive_continuity()` | "对话连续性"→"系统是否理解当前话题" |
| 心智模型骨架 | `experience_abstractor._extract_skeleton()` | "经验匹配器"→"触类旁通的抽象能力" |
| 本能升级路径 | `skill_emergence.automation_level` | "技能存储器"→"本能编码器" |
| 临时工具工坊 | `tool_builder._synthesize_tool_code()` | "代码生成器"→"运行时锻造能力" |

**原则：采纳宏大方案的"世界观"，执行轻量改造的"方法论"。不新建模块，增强现有模块。**

## 二、核心原则（不可违背）

1. **永不放弃** — 问题没有解决不了的，只有想不想得到方法
2. **追求本质** — 从第一性原理出发
3. **先规划，再更新行动指南，然后按步骤执行**
4. **代码验证靠运行而非推理**
5. **三思后行** — 先理解全景再审视局部，先搜索既有讨论再行动，先根因思考再修复
6. **不再替系统做决定，而是让系统自己做决定** — 不替系统修工具，让系统自己修；不替系统加约束，让系统自己学

## 四、行动前自检流程（R4强制）

每次修改代码或提出方案前，必须完成：

1. **理解全景** — 架构、哲学、看板历史、路线图阶段，不盯着局部
2. **搜索既有讨论** — 看板/路线图/架构分析，不重新发明轮子
3. **根因思考** — 问题是孤立故障还是未落地的架构原则？
4. **标本兼治** — 热修复(P0)与架构方案分离
5. **七维自检** — 全部通过才行动
6. **最优判断** — 依赖链排序，不做的事也明确列出

### 断裂管线详细分析

#### P0-1: FailureClassifier的`auto_fix`是死字符串

```python
# failure_classifier.py L30 — auto_fix只是描述性文字
"auto_fix": "触发实体归一化+别名映射",  # ← 没有任何代码执行这个策略

# 调用链现状：
chat_orchestrator → FailureClassifier.classify() → record_failure() → 写入DB
                                                              ↓
                                                         到此为止 ❌
                                                         auto_fix从未被消费
```

**修复方向**：在`chat_orchestrator`或`never_give_up`中消费`get_taxonomy_info(category)["auto_fix"]`，将字符串策略映射为可执行的动作。

#### P0-2: AuditLogger写入后无人消费

```python
# audit_logger.py — 写入audit_logs.jsonl
AuditLogger.log(query, intent, result, reflection)
                    ↓
            audit_logs.jsonl  ← 只有get_recent_failures()可读
                    ↓
            无任何模块定期读取并触发学习 ❌
```

**修复方向**：在`reflection_pipeline`或`sleep_consolidation`中定期消费`AuditLogger.get_recent_failures()`，将审计发现注入学习回路。
