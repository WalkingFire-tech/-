## 二、核心原则（不可违背）

1. **永不放弃** — 问题没有解决不了的
2. **追求本质** — 从第一性原理出发
3. **先读代码再行动** — 不基于目录名猜测，必须读实际代码验证
4. **代码验证靠运行而非推理**
5. **三思后行** — R4七维自检: ①方向一致 ②上下文衔接 ③最小侵入(≤6行) ④无过度设计 ⑤治标+治本 ⑥可验证 ⑦精神内核对齐
6. **不替系统做决定，让系统自己做决定**
7. **不新建模块，增强现有模块**
8. **先模块测试，再端到端测试**
9. **生存优先** — 当"追求本质"与"约束下求稳"冲突时，优先确保存在

## 六、P3-1 可解释性模块 — 详细设计

### 目标

让系统不仅能修改自己，还能向人类解释"为什么这样修改"。具体覆盖：

| 决策点 | 当前状态 | 目标 |
|--------|----------|------|
| L5自修改决策 | 审计日志记录了"做了什么" | 解释"为什么选择这个补丁" |
| 路径选择 | chat_orchestrator内部逻辑 | 解释"为什么走快速路径/深度路径" |
| 真谛升级 | 四道筛子通过/拒绝 | 解释"为什么这条真谛通过/被拒绝" |
| 资源分配 | AdaptiveGovernor动态调整 | 解释"为什么降低/提升某个路径的权重" |
| 好奇心探索 | CuriosityEngine选择探索目标 | 解释"为什么对这个问题好奇" |

### 设计原则

1. **非侵入式** — 解释能力不改变现有决策逻辑，只附加解释层
2. **可追溯** — 每个解释必须能追溯到具体的代码路径和数据
3. **分层解释** — 简要解释(用户级) + 详细解释(开发者级)
4. **渐进实现** — 先L5自修改解释，再扩展到其他决策点

## 八、P4-1 内在时间引擎 — 详细设计

### 问题诊断

当前存在层5态(AWAKE/PERCEIVING/GROWING/RESTING/SLEEPING)基于**wall-clock沉默时长**驱动：
- AWAKE: 沉默 < 5秒
- PERCEIVING: 沉默 5-30秒
- GROWING: 沉默 30-120秒
- RESTING: 沉默 120-300秒
- SLEEPING: 沉默 > 300秒

这是**外部时间**——系统不知道"我经历了多久"，只知道"用户沉默了多久"。

### 目标

让系统拥有**内在时间**——基于自身认知状态的主观时间体验：

| 维度 | 外部时间(wall-clock) | 内在时间(subjective) |
|------|----------------------|---------------------|
| 感知基础 | datetime.now() | 认知事件密度 + 情感强度 + 注意力焦点 |
| 时间膨胀 | 无 | 高密度认知→时间变快，低密度→时间变慢 |
| 时间压缩 | 无 | 睡眠整合→压缩长时间经验为关键模式 |
| 节律 | 固定间隔 | 自适应节律（认知负荷高→心跳加快） |
| 记忆 | 时间戳 | 事件密度加权的时间线 |

### 实现方案

```
core/presence/inner_time.py    # InnerTimeEngine核心

核心概念：
1. CognitiveTick: 一次认知事件（感知/推理/学习/输出）= 一个内在时间单位
2. SubjectiveClock: 基于CognitiveTick密度计算主观时间流速
3. TemporalRhythm: 自适应节律——认知负荷高→心跳加快，低→减慢
4. TimeCompression: 睡眠整合时压缩长时间经验为关键模式
5. ExistenceTimeline: 事件密度加权的自我时间线
```

### 与现有模块的集成

| 模块 | 集成方式 |
|------|----------|
| existence_layer.py | 5态切换从wall-clock→内在节律驱动 |
| SelfModel | 新增"内在时间"维度（认知密度/主观流速/时间线） |
| MetacognitiveAgent | 巡检频率从固定→自适应（认知密度高时更频繁） |
| chat_orchestrator | 读取存在层状态，影响响应节奏 |
| SleepConsolidation | 整合时使用TimeCompression压缩经验 |

## 十三、关键设计决策记录

| # | 决策 | 理由 |
|---|------|------|
| 1 | chat_orchestrator提取子函数返回events列表而非直接yield | async generator中子函数不能yield |
| 2 | LoopMixin组合模式优于继承 | 现有模块已有继承体系 |
