# 从"顾问"到"行动者"——系统自主执行能力跃迁

> 来源：2026年7月12日深度讨论，用户端到端测试"读取串口3并在地图上标记"暴露核心断裂

## 核心洞察

### 洞察1：系统是"顾问"不是"行动者"

| 用户得到的 | 用户期望的 |
|-----------|-----------|
| "请运行这段代码" | "经纬度是 30.84N, 121.45E" |
| "请安装 pyserial" | "数据已读取" |
| "用 folium 生成地图" | "地图已打开，这是你的位置" |

**本质**：用户不在乎管道里流的是什么——只要水龙头出水就行。代码不是终点，结果才是。

### 洞察2：系统已有"手"但没伸出去

代码级验证发现，系统**已经具备**自主执行能力，但关键模块未被调用：

| 模块 | 设计意图 | 实际状态 |
|------|---------|---------|
| `capability_creation_loop.py` | 自主锻造+验证+注册工具 | chat_orchestrator中**0次引用** |
| `persistent_solver` tool_execution | 失败后重试调用工具 | 意图硬编码为complex_query |
| `tool_builder`沙箱 | 运行时工具生成 | 禁止os/subprocess，无法访问硬件 |

**教训**：系统不是"不会做"，而是"卡在做了但没跑通，然后退出了"。修复不是重写架构，而是接通断裂的管线。

### 洞察3：新建模块是错误方向

本轮新建了`auto_execution_loop.py`，但系统已有`capability_creation_loop.py`实现类似功能。这违反了"不新建模块，增强现有模块"原则。

**教训**：在新建模块前，必须先搜索现有代码中是否已有类似实现。目录名猜测≠代码实际状态。

### 洞察4：存在层是纯接收端

chat_orchestrator只向存在层写入（`user_interaction()`/`receive_signal()`），**从不读取状态**。存在层5态（AWAKE/PERCEIVING/GROWING/RESTING/SLEEPING）不影响任何决策。

**修复方向**：不是线性读状态，而是注入7路径并行的权重矩阵——sleeping切断外部API，growing提高知识检索权重。

### 洞察5：进化岛注入绕过安全协议

`active_scheduler._apply_evolved_genome()`直接操作genome_evolver数据库做全量覆盖，**违反R2渐进注入铁律**。lifespan中之前甚至没有注入。

**修复方向**：走truth_accumulator的6步认知重组安全协议（propose→sandbox→1%→20%→100%→完成/回滚）。

### 洞察6：gene_safety_violations始终为0不是传感器坏了

验证发现传感器已安装且工作正常。0违规是因为当前基因变异幅度保守（delta 0.01-0.02），都在安全边界内。但这可能意味着**安全边界设得太宽**。

## 端到端测试记录

### 测试：读取串口3并在地图上标记

**结果**：系统尝试14-15种方法全部失败

**断裂链**：
```
1. 用户输入 "读取串口3并在地图上标记"
2. CognitiveDispatcher 意图识别失败（没有匹配到 hardware）
3. 走了 "复杂问题" 兜底路径（而不是 SerialPortTool）
4. 复杂问题路径调用了 "自我推理" + "多策略并行"
5. 这些策略生成的是 "文本回答"，而不是 "执行动作"
6. 最终返回 "我做不到" 的说明，而不是 GPS 经纬度
```

**修复后验证**：
- 意图识别："读取串口3"→hardware(0.67)，"读取COM3"→hardware(0.90) ✅
- 参数提取：port=COM3, action=read, hint=serial_port ✅
- 工具规划：serial_port排第一 ✅
- 自主执行回路：串口扫描1次成功，地图生成2次成功（自动安装folium） ✅

## 修复依赖链

```
P0-1: 进化岛注入升级为安全协议（R2铁律红线）
  ↓
P0-2: 合并auto_execution_loop→capability_creation_loop（消除功能重叠）
  ↓
P0-3: capability_creation_loop接入chat_orchestrator（工具失败分支）
  ↓
P0-4: persistent_solver意图修复（hardware不走complex_query）
```

## 关键教训总结

1. **结果交付意识**：用户要的是结果不是代码。代码生成不是终点，执行并返回结果才是。
2. **先读代码再行动**：不基于目录名猜测，必须读实际代码验证。新建模块前先搜索现有实现。
3. **R2铁律不可妥协**：任何注入必须走渐进安全协议。直接写DB全量覆盖=自杀。
4. **7路径并行下的策略注入**：线性读状态对7路径并行无效，必须注入权重矩阵。
5. **不新建模块**：新概念应融入现有模块。auto_execution_loop.py是错误决策，应合并回capability_creation_loop。
