# 本质推理器 — 6步推理架构

> 来源：core/essence_reasoner.py，2026年6月设计实现

## 核心思路

对AI生成的回答进行"本质推理与自洽验证"，确保回答不是表面拼凑，而是经得起推敲的。

## 6步推理流程

```
事实提取 → 第一性原理推理 → 自洽性检查 → 跨域一致性 → 反向归谬 → web校验
```

### 第1步：事实提取
- 从回答中提取可验证的事实声明
- 标注领域（物理/化学/生物/天文/通用）
- 标注类型（scientific/definition/claim）
- **代码块占比>40%时跳过**——代码问题不做科学事实提取

### 第2步：第一性原理推理链
- 每个事实声明追溯到基本原理
- 标注是否可追溯（traceable）
- 标注推理断裂点（gap）

### 第3步：自洽性检查
- 逻辑谬误检测（循环论证/滑坡/假二选一/诉诸权威）
- 事实声明之间的矛盾检测（含主语一致性检查）
- 推理链断裂检测
- **悖论问题跳过推理链断裂检查**

### 第4步：跨域一致性
- 天文-物理：轨道力学一致性
- 化学-物理：热力学一致性
- 生物-化学：分子机制一致性

### 第5步：反向归谬
- 对每个事实声明构造反例
- 如果反例不成立，则事实更可信
- 内置反例库（如：火星蓝色散射→不是大气反射）

### 第6步：web事实校验
- DuckDuckGo API搜索验证
- 只对高风险科学事实校验
- 超时2秒，最多2个事实，首次失败立即跳过

## 本质闸门

在推理之前先问三个问题：
1. 剥离表象——这个问题的本质是什么？
2. 定义真谛标准——什么样的答案才算触及本质？
3. 设定无知红线——我承认自己不知道什么？

闸门输出示例：
- "算法正确性与工程可行性——本质是'代码能否正确运行'"
- "逻辑自指或因果循环——本质是'定义边界'问题"

## 关键设计决策

| 决策 | 原因 |
|------|------|
| 代码问题跳过事实提取 | 代码内容被误判为科学事实 |
| 悖论提前返回 | 悖论不适用基本原理追溯，应给出定义框架 |
| 矛盾检测加主语检查 | "天空是蓝色"和"不是太阳"不矛盾 |
| web校验快速失败 | DuckDuckGo不可用时避免浪费15秒 |
