# 流式聊天9阶段架构

> 来源：backend/chat_stream.py，2026年6月设计实现

## 核心思路

聊天不是简单的"输入→输出"，而是一个完整的认知过程：识别→思考→验证→学习。每个阶段通过SSE实时推送，让用户看到系统的思考过程。

## 9阶段流程

```
阶段1: 意图识别
  ↓ (简单意图直接回复)
阶段2: 简单意图处理 (greeting/confirmation/history/challenge)
  ↓ (复杂意图)
阶段2.5: 本质闸门 + 方法论发现 + 真谛类推
  ↓
阶段3: 多策略并行尝试 (5条路径全部并行)
  ↓
阶段4: 对比择优
  ↓
阶段4.5: 本质推理与自洽验证 (含多源交叉验证)
  ↓
阶段5: 自我验证 (含代码验证 + 科学免责领域感知)
  ↓
阶段6: 精神内核验证
  ↓
阶段7: 反思学习 + 基因微调 + 技能涌现 + 真谛沉淀
  ↓
阶段8: 后台持续进化 (认知代谢 + 压力测试)
```

## 关键设计决策

### 为什么9个阶段？
每个阶段解决一个特定问题：
- 阶段1-2：快速路径，简单问题2秒内回复
- 阶段2.5：在动手之前先想清楚"怎么解决"
- 阶段3-4：多方案并行，择优选取
- 阶段4.5：确保回答经得起推敲
- 阶段5-6：质量保证
- 阶段7-8：从每次交互中学习

### 为什么多策略并行？
- 5条路径同时尝试：规则推理 + 经验池 + 知识库 + Ollama + 外部API
- 不依赖任何单一来源
- 任何一条路径成功就能给出回复
- 多条路径成功则对比择优

### 为什么本质闸门在推理之前？
- 先确定"如何解决"再解决
- 避免用错误的方法解决正确的问题
- 代码问题走代码验证，科学问题走本质推理，悖论走定义框架

## SSE事件格式

```json
{"type": "step", "phase": "意图识别", "status": "running", "detail": "分析问题类型..."}
{"type": "step", "phase": "意图识别", "status": "done", "detail": "识别为complex_query"}
{"type": "result", "response": "...", "attempts": [...], "intent": "complex_query"}
```

## 性能指标

| 问题类型 | 典型耗时 | 关键路径 |
|----------|----------|----------|
| 问候 | 2s | 阶段1→2直接回复 |
| 代码工程 | 30-40s | 阶段1→2.5→3→4→5→7 |
| 科学事实 | 60-80s | 阶段1→2.5→3→4→4.5→5→7 |
| 悖论 | 30-40s | 阶段1→2.5→3→4→4.5(提前返回)→7 |
